# Plan: PWA Setup with Dev and Production Dual-Origin Support

**Status:** approved
**Created:** 2026-04-19
**Author:** user + planitect

## Goal

Turn Voilot into a proper installable PWA on mobile devices, while maintaining a frictionless development workflow. Both a production build and a live dev version should be installable side-by-side on the same phone, each with full microphone access. Provide a polished mobile install experience with a full-screen prompt overlay, and reuse the same overlay for update notifications in production.

## Context

- The `@vite-pwa/nuxt` module is already installed (`^0.10.0` in devDependencies) but disabled because service worker caching caused stale JS on mobile during development.
- Apple mobile web app meta tags (`apple-mobile-web-app-capable`, `black-translucent` status bar) are already in `nuxt.config.ts`.
- No `public/` directory exists yet — no manifest file or app icons are in place.
- HTTPS is provided via Tailscale (`tailscale serve`), which is required for microphone access (`getUserMedia` needs a secure context).
- Currently everything runs on a single machine. Production will eventually move to a dedicated host.
- The frontend is a static Nuxt 3 SPA (`ssr: false`, `nuxt generate`) served by Nginx in production.
- `app.vue` contains a stale SW unregister script that must be removed when the module is re-enabled.

## Decisions

These questions from the original draft have been resolved:

| Question | Decision |
|---|---|
| App icon design | Placeholder text-based icons: uppercase **V** (blue) for prod, lowercase **v** (purple) for dev |
| Dev PWA hostname | Separate Tailscale hostname (e.g. `voilot-dev`) — cleaner PWA identity than port-based |
| Update strategy (prod) | Show an update prompt overlay (`skipWaiting: false`, `registerType: 'prompt'`) — user taps "Update now" |
| Update strategy (dev) | Silent auto-update (`skipWaiting: true`) — no prompts during development |
| Install prompt trigger | Auto-show once on first mobile visit, dismiss stored in `localStorage` |
| Install prompt placement | Landing page (session list) only — never interrupts a session |
| Already-installed behavior | Hide the install overlay entirely; reuse the same overlay for update prompts |

## Approach

### 1. App Icons — Placeholder with Dev/Prod Differentiation

Generate simple text-based SVG icons, rasterized to required PNG sizes.

**Production icons:**
- Large uppercase **V** in blue (`#3b82f6`) on dark background (`#0f172a`)
- Files: `frontend/public/icons/icon-192x192.png`, `icon-512x512.png`, `icon-maskable-512x512.png`, `apple-touch-icon.png` (180x180)

**Development icons:**
- Small lowercase **v** in purple (`#a855f7`) on dark background (`#0f172a`)
- Files: `frontend/public/icons/dev/icon-192x192.png`, `dev/icon-512x512.png`, `dev/icon-maskable-512x512.png`, `dev/apple-touch-icon.png`
- Purple matches the existing "voice ON" accent color in the UI

Source SVGs are kept in the repo for easy future replacement.

The icon set is selected in `nuxt.config.ts` based on `process.dev`, which toggles the manifest icon paths.

### 2. Re-enable `@vite-pwa/nuxt` with Environment-Aware Configuration

Uncomment the module in `nuxt.config.ts` and add a full `pwa` config block.

**Shared config:**
- Manifest fields: `name`, `short_name`, `start_url: "/"`, `display: "standalone"`, `background_color: "#0f172a"`, `theme_color: "#0f172a"`
- Manifest `name`/`short_name`: `"Voilot"` in prod, `"Voilot Dev"` in dev (via `process.dev`)
- Icon references: point to prod or dev icon directory based on environment
- Add `apple-touch-icon` link in the Nuxt head config

**Development mode:**
- `devOptions.enabled: true` — SW registers in dev for install prompt / standalone mode
- `devOptions.type: 'module'` — modern SW support
- `skipWaiting: true` — silent auto-update, no prompt
- No runtime caching rules — HMR and live changes work normally

**Production mode:**
- `registerType: 'prompt'` — we control SW activation via the overlay
- `skipWaiting: false` — new SW waits until user confirms update
- `clientsClaim: true` — active SW claims all clients on activation
- Workbox runtime caching:
  - `NetworkFirst` for HTML / navigation requests
  - `CacheFirst` for static assets (JS, CSS, images, audio blip files)
- Precache the generated static assets from `nuxt generate`
- `maximumFileSizeToCacheInBytes` set high enough to include audio feedback files

**Cleanup:**
- Remove the stale SW unregister script from `app.vue`

### 3. Unified PWA Prompt Overlay — Install and Update

A single full-screen overlay component handles both install prompts (for new mobile visitors) and update prompts (for installed PWA users). Mounted on the landing page only.

#### 3.1 Composable: `frontend/composables/usePwaPrompt.ts`

Module-level singleton (same pattern as `useAudioFeedback`) that manages all PWA prompt state.

**State machine — `promptType` reactive ref:**

```
null ─────────────────── (hidden: desktop, dismissed, or standalone with no update)
  │
  ├─ 'install-android' ── first mobile visit, Chrome/Android, beforeinstallprompt captured
  ├─ 'install-ios' ────── first mobile visit, iOS Safari, no native install API
  └─ 'update' ─────────── SW in waiting state, new version available (overrides install)
```

**Responsibilities:**
- Capture `beforeinstallprompt` event (Chrome/Android) — store the event, prevent default
- Detect iOS Safari via user agent (no `beforeinstallprompt` on iOS)
- Detect standalone mode via `matchMedia('(display-mode: standalone)')` and `navigator.standalone`
- Listen for SW `waiting` state via `@vite-pwa/nuxt`'s `useRegisterSW` composable
- Track "install dismissed" flag in `localStorage` (key: `voilot-pwa-install-dismissed`)
- Desktop detection — never show install prompt on desktop

**Exported API:**
- `promptType: Ref<'install-android' | 'install-ios' | 'update' | null>`
- `isStandalone: Ref<boolean>`
- `triggerInstall(): Promise<void>` — calls captured `beforeinstallprompt.prompt()`
- `triggerUpdate(): void` — sends `SKIP_WAITING` to waiting SW, reloads page
- `dismiss(): void` — hides overlay, sets localStorage flag (install only; update can be dismissed but reappears next visit)

**Logic flow:**
1. On init: check standalone → if yes, only watch for SW updates
2. If not standalone + mobile + not dismissed → set `promptType` to `install-android` or `install-ios`
3. When SW enters `waiting` state → set `promptType` to `update` (overrides any install state)
4. Desktop → `promptType` always `null`

#### 3.3 Mounting

- `<PwaPrompt />` is rendered in `frontend/pages/index.vue` (session list page)
- The composable initializes globally (captures `beforeinstallprompt` early via a Nuxt plugin or top-level import), but the overlay only renders on the landing page
- When navigating to a session and back, the overlay reappears only if `promptType` is non-null and not dismissed

### 4. Dual-Origin Setup for Dev and Production on Mobile

Both versions are installable as separate PWAs because they have distinct origins.

**Single-machine setup (current):**
- Production: `https://voilot.<tailnet>.ts.net` → `tailscale serve` → port 80 (Nginx/Docker)
- Development: `https://voilot-dev.<tailnet>.ts.net` → `tailscale serve` → port 3000 (Nuxt dev)

**Dual-machine setup (future):**
- Production moves to a dedicated Mac with its own Tailscale hostname
- Dev stays on the laptop — origins are naturally different

Each origin gets its own microphone permission grant.

### 5. Microphone and Audio Considerations

- Both origins get their own separate microphone permission
- The standalone PWA window has the same Web Audio API capabilities as the browser
- Mobile audio autoplay restrictions still apply — the existing user-gesture-triggered audio unlock pattern carries over
- Verify blip and pulse sounds play correctly in the installed PWA context
- Test on both iOS Safari (WebKit-based PWA shell) and Android Chrome

### 6. Offline Behavior

- Voilot is inherently online — the service worker caches the app shell for fast startup only
- API calls (`/api/*`, `/ws/*`) and WebSocket traffic are never cached
- When the backend is unreachable, the app opens from cache and shows its existing connection error state

## Out of Scope

- Custom icon design (placeholders only — to be replaced with proper branding later)
- Offline fallback page (app shows connection error state naturally)
- Push notifications
- Background sync

## Acceptance Criteria

- `@vite-pwa/nuxt` is re-enabled and configured with dev/production-aware caching
- A valid web manifest with proper icons is generated and served
- The app is installable as a PWA on iOS and Android
- Dev and production versions can be installed side-by-side with distinct names and icons (blue V vs purple v)
- On first mobile visit, a full-screen install prompt overlay appears (auto-dismissed after one viewing)
- On Android, the overlay triggers the native install prompt; on iOS, it shows manual instructions
- In production, when a new SW version is waiting, the overlay shows an "Update now" prompt on the landing page
- In dev mode, SW updates apply silently — no prompts
- Microphone access works in the installed PWA on mobile
- In dev mode, no caching occurs — code changes reflect immediately
- In production, the app shell is cached for fast startup but API calls are never cached
- The stale SW unregister script in `app.vue` is removed
