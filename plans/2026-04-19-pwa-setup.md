# Plan: PWA Setup with Dev and Production Dual-Origin Support

**Status:** draft
**Created:** 2026-04-19
**Author:** user + planitect

## Goal

Turn Voilot into a proper installable PWA on mobile devices, while maintaining a frictionless development workflow. Both a production build and a live dev version should be installable side-by-side on the same phone, each with full microphone access.

## Context

- The `@vite-pwa/nuxt` module is already installed but disabled because service worker caching caused stale JS on mobile during development.
- Apple mobile web app meta tags (`apple-mobile-web-app-capable`, `black-translucent` status bar) are already in `nuxt.config.ts`.
- No `public/` directory exists yet — no manifest file or app icons are in place.
- HTTPS is provided via Tailscale (`tailscale serve`), which is required for microphone access (`getUserMedia` needs a secure context).
- Currently everything runs on a single machine. Production will eventually move to a dedicated host.
- The frontend is a static Nuxt 3 SPA (`ssr: false`, `nuxt generate`) served by Nginx in production.

## Approach

### 1. Web App Manifest and Icons

- Create `frontend/public/manifest.webmanifest` (or let `@vite-pwa/nuxt` generate it from config).
- Required manifest fields:
  - `name`: "Voilot"
  - `short_name`: "Voilot"
  - `start_url`: "/"
  - `display`: "standalone"
  - `background_color`: "#0f172a" (matches existing theme-color)
  - `theme_color`: "#0f172a"
  - `icons`: at least 192x192 and 512x512 PNG, plus a maskable variant
- Generate icons from a source SVG/PNG. Consider using `@vite-pwa/assets-generator` to produce all required sizes.
- Add an Apple touch icon (`apple-touch-icon`) link in the Nuxt head config.

### 2. Re-enable `@vite-pwa/nuxt` with Environment-Aware Caching

Configure the module differently for dev vs production:

**Development mode (no caching):**
- Enable `devOptions.enabled: true` so the service worker registers in dev.
- Use `devOptions.type: 'module'` for modern SW support.
- The dev SW provides the PWA shell (install prompt, standalone mode, manifest) but does not precache or cache anything at runtime.
- Hot module reload and live changes work normally.

**Production mode (caching):**
- Use `workbox` strategy with `NetworkFirst` for API/HTML and `CacheFirst` for static assets (JS, CSS, images, audio files).
- Precache the generated static assets from `nuxt generate`.
- Set a reasonable `maximumFileSizeToCacheInBytes` to include audio blip files.
- Configure `skipWaiting: true` and `clientsClaim: true` so updates apply immediately — avoids the stale JS problem that led to disabling PWA in the first place.
- Consider a "new version available" prompt if immediate activation causes issues.

### 3. Dual-Origin Setup for Dev and Production on Mobile

Both versions should be installable on the same phone as separate PWAs. Since PWAs are scoped by origin, each needs a distinct URL.

**Single-machine setup (current):**
- Production (Docker stack): served on port 80 via Nginx, exposed through Tailscale as `https://voilot.<tailnet>.ts.net`
- Development (Nuxt dev server): served on port 3000, exposed through Tailscale as a second hostname or a different Tailscale serve entry, e.g. `https://voilot-dev.<tailnet>.ts.net`
- Tailscale config example:
  - `tailscale serve --bg --https=443 --set-path / http://localhost:80` on the production hostname
  - `tailscale serve --bg --https=443 --set-path / http://localhost:3000` on the dev hostname
- Alternative: use the same hostname with different ports (e.g. `https://voilot.<tailnet>.ts.net:8443` for dev), though separate hostnames are cleaner for PWA identity.

**Dual-machine setup (next step):**
- Production moves to a dedicated Mac with its own Tailscale hostname (e.g. `voilot.<tailnet>.ts.net`).
- The Mac runs the Docker Compose stack (Nginx, backend, TTS, STT) and the agent backend (OpenCode).
- Dev stays on the laptop with its own Tailscale hostname (e.g. `voilot-dev.<tailnet>.ts.net`).
- No additional config needed — origins are naturally different since each Mac has its own Tailscale identity.

**Differentiation:**
- Give the dev PWA a distinct `name` ("Voilot Dev") and different icon color/badge so it's visually distinguishable on the phone's home screen.
- Use an environment variable or Nuxt runtime config to toggle the manifest name and icon set.

### 4. Microphone and Audio Considerations

- Both origins get their own separate microphone permission — the user grants access once per origin.
- The standalone PWA window has the same Web Audio API capabilities as the browser, but avoids the browser chrome which is better for a voice-first app.
- Mobile audio autoplay restrictions still apply inside a PWA. The existing user-gesture-triggered audio unlock pattern (tap to start voice) should carry over. Verify that blip and pulse sounds play correctly in the installed PWA context.
- Test on both iOS Safari (WebKit-based PWA shell) and Android Chrome.

### 5. Offline Behavior

- Voilot is inherently online (needs the backend for STT, TTS, and agent communication).
- The service worker should cache the app shell so the PWA opens instantly, then show a "no connection" state if the backend is unreachable.
- Do not cache API responses or WebSocket traffic.

## Open Questions

- What should the Voilot app icon look like? Is there an existing design or should we create a simple placeholder?
- Should the dev PWA use a completely separate Tailscale hostname (e.g. `voilot-dev`) or a port-based separation on the same hostname?
- Do we want a "new version available, tap to update" prompt in production, or is silent auto-update (`skipWaiting`) acceptable?
- Should the service worker precache audio feedback files (blips, pulses) so they play even on flaky connections?

## Acceptance Criteria

- `@vite-pwa/nuxt` is re-enabled and configured with dev/production-aware caching.
- A valid web manifest with proper icons is generated and served.
- The app is installable as a PWA on iOS and Android.
- Dev and production versions can be installed side-by-side on the same phone with distinct names and icons.
- Microphone access works in the installed PWA on mobile.
- In dev mode, no caching occurs — code changes reflect immediately.
- In production, the app shell is cached for fast startup but API calls are never cached.
